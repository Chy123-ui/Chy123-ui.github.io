1.this是什么？

this 是 JS 中最核心的关键字之一，本质是 “函数运行时的上下文对象” 。this 指向 = 函数的调用者

2. this 的四大绑定规则（普通函数）

JavaScript 的 this 有四套核心规则，按优先级从低到高：

2.1 默认绑定（独立调用）

函数被直接调用，没有对象：

独立调用情况下，this = 全局对象（或 undefined）。

2.2 隐式绑定（作为对象的方法调用）

格式：对象.函数名()

当函数作为对象的“方法”调用时：

谁“点”了这个函数，this 就指向谁。

方法调用（object.method()）

运行时发生了什么（逐步）

  1. 引擎看到 whiteRabbit.speak("Hello!")。
  2. 它先做“属性查找”：在 whiteRabbit 上找到 speak，这返回函数值 speak。
  3. 接着“调用”这个函数，同时记录调用者对象是 whiteRabbit。
  4. 在函数内部，this 被设置为那个调用者：this === whiteRabbit。
  5. 因此 this.type 就是 "white"，输出 "The white rabbit says 'Hello!'"。

结论：object.method() → this 就是那个 object。

将方法赋给变量然后调用（函数丢失“主人”）

发生了什么

  1. speakFunc 只是函数的引用，不再通过 whiteRabbit. 调用。
  2. 调用时没有“调用者对象”，因此 this 不是 whiteRabbit。
  3. 在严格模式下 this === undefined；非严格模式下 this 是全局对象（浏览器里是 window）。
  4. this.type 可能是 undefined 或抛错（如果严格模式下访问 this.type 会报错）。

结论：把方法当作普通函数调用（没有对象点在前面）就丢失了 this。

call/apply 的唯一核心目的：强行把函数的 this 改成你指定的对象，同时立即执行这个函数。

4. 为什么箭头函数没有自己的 this？

因为箭头函数在设计时主要用于：

  • 回调
  • 内联函数
  • 保持词法作用域

如果它有自己的 this，会和 class/method 的 this 冲突，代码会变复杂。

因此，设计者直接禁掉了它的 this，让它“从外面拿”，就像：

的语法糖。

5. this 的本质

this 不是词法作用域变量，不是根据代码写在哪里决定的。
它是执行时的上下文对象，由函数的调用方式决定。
箭头函数除外，它从外层作用域继承 this。
